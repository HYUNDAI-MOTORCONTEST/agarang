# 아가랑 Google Drive 멀티 에이전트 협업 규칙

## 1. 절대 접근 경계 (Scope Guardrail)

1. **오직 `아가랑` 폴더와 그 하위 항목만 접근한다.**
   - 프로젝트와 무관한 외부 드라이브 폴더·파일은 조회·읽기·이동·수정을 금지한다.
2. **전체 드라이브를 훑는 명령은 실행하지 않는다.**
   - 금지 예: `gdrive readonly ls` (인자 없이 루트 나열), `gdrive readonly recent`, `gdrive readonly starred`, `gdrive readonly shared-drives`, 조건 없는 광범위 `search`.
   - `아가랑` 루트 폴더 ID는 git 제외 파일(`.dev/gdrive.env`)에서 읽거나, 없을 때만 아래 단일 검색으로 폴더 ID만 확인한다.
     ```bash
     gdrive readonly search --name-exact "아가랑" --type folder --json
     ```
   - 루트 ID를 얻은 뒤에는 반드시 `<AGARANG_ROOT_ID>` 또는 그 하위 ID를 명시한 명령(`tree <ID>`, `ls <ID>`, `search --parent-id <ID>`, `info <ID>`)만 사용한다.
3. **파괴적·외부 노출 작업 금지**
   - `trash`, `untrash`, `empty-trash`, `remove-permission`, `share --type anyone` 및 `아가랑` 폴더 밖으로의 `mv`는 사용자 명시 요청 없이 절대 실행하지 않는다.

## 2. 표준 패키지 구조 (`아가랑/` 하위)

루트(`아가랑/`)에는 마스터 인덱스 문서(`00_아가랑_프로젝트_한눈에보기`)와 아래 4개 패키지 폴더만 둔다. **새 파일이나 폴더를 루트에 직접 올리지 않는다.**

| 패키지 폴더 | 담당 산출물·문서 | 하위 폴더 예시 |
| --- | --- | --- |
| `01_기획_및_1차제출/` | 기획안(`.md`/`.pdf`), 접수양식(`.docx`), 제출 체크리스트(`.xlsx`), 메일 초안, 공모전 기준 규칙(`공모전_기준규칙_rules.md`) | — |
| `02_시연_및_디자인_산출물/` | 시연 영상 대본, 에뮬레이터 실화면 영상, 편집본, Release APK, UI 스크린샷, 로고·아이콘 에셋 | `시연_실화면_YYYY-MM-DD/`, `빌드_APK/`, `UI_스크린샷_YYYY-MM-DD/`, `로고_시안_YYYY-MM-DD/`, `아이콘_14종_*` |

| `04_서류통과후_2차PT_로드맵/` | 1차 통과 이후 P1/P2 구현 로드맵, AI 기능 후보 검토, 2차 PT 스토리보드·대본 | — |

## 3. 멀티 에이전트 작업 절차 (충돌·중복 방지)

1. **Read-before-Write (작업 전 트리 확인)**
   - 업로드·폴더 생성 전에 먼저 대상 범위를 읽어 다른 에이전트나 팀원이 이미 올린 폴더·파일이 있는지 확인한다.
     ```bash
     gdrive readonly tree <AGARANG_ROOT_ID>
     ```
2. **기존 폴더·파일 재사용 우선**
   - 같은 주제·날짜의 산출물이 이미 있으면 루트에 새 폴더를 만들지 말고 해당 패키지 폴더 또는 기존 하위 폴더 안에 배치한다.
   - 같은 문서를 고칠 때는 새 사본을 계속 만들지 말고 `gdrive mutate update <FILE_ID> <LOCAL_PATH>`로 인플레이스 갱신한다(기존 File ID·링크·공유 권한 유지).
   - 이전 버전을 보존해야 할 때는 삭제하지 않고 하위 `이전_*` 폴더(예: `이전_UI_개선전_62장/`)로 정리한다.
3. **네이밍 규칙**
   - 영상·캡처·디자인 묶음 폴더: `<카테고리>_YYYY-MM-DD` (내부에 가능하면 `README.md` 또는 `manifest.json` 동봉)
   - 단일 문서: `아가랑_<주제>_YYYY-MM-DD` (팀원 검토·공동 편집용 문서는 `--mime-type "application/vnd.google-apps.document"`로 Google Docs 변환 권장)
   - 파일 이동(`mutate mv`) 전후로 대상 부모가 `아가랑` 하위인지 확인해 공유 권한이 빠지지 않게 한다.
4. **`00_아가랑_프로젝트_한눈에보기` 동기화**
   - 주요 산출물(APK, 시연 영상 묶음, 새 로드맵, 공식 제출본 등)을 추가·이동·갱신했다면:
     1. 먼저 현재 `00_아가랑_프로젝트_한눈에보기`를 로컬 임시 경로로 `gdrive readonly export` 해 최신 내용을 읽는다(다른 에이전트의 최근 반영 내용을 덮어쓰지 않기 위함).
     2. 변경된 항목과 링크만 반영한 뒤 `gdrive mutate update`로 갱신한다.
     3. 대량 병렬 작업 중 동시 수정 위험이 크면 사용자 보고 시 인덱스 반영 필요 항목(파일명·경로·File ID)을 명시한다.

## 4. 보안 · 공모전 익명성 준수

- **Git 저장소 분리:** Drive 파일/폴더 ID, Drive 공유 URL, 팀원 실명·이메일·계정 정보는 **절대 Git 저장소(코드, 문서, 스킬, 커밋 메시지)에 넣지 않는다.** 로컬 캐시가 필요하면 `.gitignore` 대상인 `.dev/` 아래에만 둔다.
- **민감정보 업로드 금지:** Drive 문서에도 API 키, 서명 키(`*.jks`), 비밀번호, 인증 토큰을 올리지 않는다.
- **제출 자료 익명성:** 공개 GitHub 레포·시연 영상·UI 캡처와 연결되는 자료는 `docs/contest/rules.md` 6장(익명성 규정)을 지킨다.

## 5. 작업 후 보고 항목

Drive 작업을 마치면 아래를 짧게 보고한다.

2. Drive File/Folder ID 및 웹 링크
3. `00_아가랑_프로젝트_한눈에보기` 동기화 여부 및 기존 파일·공유 권한 유지 여부
