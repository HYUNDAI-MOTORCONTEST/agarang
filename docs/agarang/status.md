## 검증과 UI 상태

- 최신 내비 보완 GCP 빌드: **공용 187개 + 서버 9개 = 196개 테스트 통과**, 실패·오류·스킵 0. 내비 36개와 울음 대응 18개 테스트에 ID·좌표 일치, 일시 재탐색, 다른 목적지 오확인 방지, 전송 전 실패·ETA 보존을 포함한다. 앱 debug·계측 APK 빌드·설치, 실제 Android 울음 대응 회귀 검증, 최종 SDK 읽기 전후 EMPTY·SAFE_GUIDING을 통과했다. 개인 기록 지문·109개 빌드 입력·설치 APK를 대조했다. [후속 검증 기록](navigation-repro.md)
- #8 GCP 검증은 공용 179개 + 서버 9개 = 188개 테스트와 앱 설치·기기 컨트롤러/저장 검증을 통과했다. 당시 빌드 입력 109개 파일과 설치 APK의 지문을 대조했다. [울음 대응 검증 기록](response.md)
- 수동/임박 진입·반복 억제·두 정차 선택·기록 후 복귀·기록 없이 완료·첫날/시설 없음/내비 실패를 재현했다. 화면 20개로 두 창 크기·주야간·주행 제한과 주차 후 상세 복원을 확인했다. 저장 확인 실패에는 대응을 유지했다. 데모와 임시 검증이 기존 개인 돌봄·준비물을 변경하지 않았다.
- #7 단계에서는 171개 테스트와 출발 선택 3가지·기록/취소·첫날·90분 지연·외출 범위·준비물 추가/재실행 복원, 주행 시작 때 입력·키보드 종료를 확인했다. [출발 예보 검증 기록](departure.md)
- #6 단계에서는 공용 137개 + 서버 9개 = 146개 테스트, 공개 시설 468건 API와 Kotlin 재수집 결과 일치, 화면·캐시를 검증했다. [시설 검증 기록](facilities.md)
- #6 실행의 내비 읽기 스모크 두 번은 `read=FAILED`였다. 11/13 후속 실행에서는 기본 내비의 ‘다시 시도’ 이후 EMPTY·READY·ETA·재연결을 다시 확인했다. 공식 예제의 경유지 ID는 반영됐지만 지리 좌표가 0,0이어서 실제 등록 성공은 확정하지 못했다. 공급자가 확인한 진입 좌표·현재 경로 접근성·호환 POI ID도 아직 없다. [내비 검증 기록](navigation-repro.md)
- 로컬에는 JDK·Android SDK가 없어 위 결과는 GCP 실행 결과다. 실행 스크립트 변경은 Bash 구문 검사와 실제 HOME/LAUNCHER 동작을 확인했다.
- 11/11~11/12 초기 캡처의 GCP AVD 화면 규격이 잘못돼 있었다. 공식 기기 프로필의 2560×1440·160dpi로 맞추고 Cold boot한 뒤 앱과 차량 시스템 UI를 다시 확인했다. 이전 규격의 시각 검증 주장은 정정했다. [화면 규격·재검증](care-records.md)
- 현재 앱의 첫 화면은 출발 예보·출발 선택·준비물·바로 기록과 큰 울음 대응 진입으로 구성했다. 글자 위계·대비·터치 크기와 실제 두 창 크기의 주간/야간을 확인했다. 전체 제품의 시각 마감·통합 검증은 남아 있다.
- 실행 가능한 제출용 release APK와 전체 시연 동선은 아직 완성되지 않았다.

다음 의존성은 #5의 유효한 경유지 결과 조회와 #6의 현재 경로·진입 접근성 공급자다. 공급자 없이 실도로 추천을 활성화하지 않는다. 해당 연결과 별개로 핵심 시나리오 통합 검증·제출 준비(#12·#13)는 진행할 수 있다. 부분 완료를 합산하지 않은 이슈 완료율은 P0 56%·전체 38%다. 시설·출발·울음 대응과 내비 보완의 검증된 상태를 로컬 커밋으로 보관했다. 원격 푸시는 하지 않았다.
