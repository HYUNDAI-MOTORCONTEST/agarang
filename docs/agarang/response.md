# 울음 대응 (#8, F4)

구현 기준: 이슈 #8, 예보 엔진 #4, 시설·정차 계획 #6, 출발 화면 #7. 확인일 2026-11-12.

## 사용자 흐름

첫 화면과 주행 요약에 96dp 이상의 ‘울음 대응’ 버튼을 둔다. 직접 누르면 대응 모드가 열린다. 예보가 IMMINENT일 때는 화면 안에서 조용히 ‘대응 확인하기 / 나중에’를 제안하며 확인 전에는 대응 화면으로 자동 전환하지 않는다. 소리·팝업·시스템 알림·마이크·자동 울음 감지는 추가하지 않았다.

정차 중에는 수유·수면·보호자 확인 착석의 최근 기준 기록, 경과 분, 계획 시각, 설정/이력/일반 참고/데모와 정보 부족을 함께 표시한다. 항목 순서는 원인 확률의 순위가 아니다. 기저귀·현재 반응 등 기록만으로 알 수 없는 상태는 직접 확인한다.

풀케어(수유시설 확인)와 가까운 정차(경로상 더 빨리 도달하는 후보)를 선택할 수 있다. #6 `StopPlanner`가 접근성·최신성·현재 여정을 확인한 후보만 사용한다. 후보 선택은 대응 계획이며 실제 내비 등록과 별도다. 실제 후보 선택은 #5의 슬롯 재조회만 시작하고, 사용자 확인 뒤 다시 조회해 등록·결과 읽기를 수행한다. 진입 → 후보 선택 → 내비 확인의 기본 3회 터치 흐름이며 실패 때는 ‘내비 추가 확인’으로 수동 재확인할 수 있다. 등록 결과가 불명확하면 성공으로 표시하거나 자동 재전송하지 않는다. 대응을 닫아도 기존 내비 요청 결과는 계속 표시한다.

돌봄을 실제로 마친 뒤 기록하면 **확정 저장을 확인한 뒤에만** 출발 예보로 돌아간다. 저장 실패·확인 실패에는 대응 화면을 유지하고 기록 상태 확인 경로를 제공한다. ‘기록 없이 돌봄 완료 확인’은 새 돌봄 기록을 만들지 않는다. 완료는 대응 흐름을 닫았다는 뜻이며 울음이나 건강 상태가 해결됐다는 판단이 아니다.

## 주행과 화면

CarUxRestrictions의 DO·NO_SETUP·NO_KEYBOARD가 제한되면 상세 근거·입력·돌봄 기록을 숨기고 핵심 요약과 정차 선택·확인·닫기 동작만 제공한다. 정차 후 현재 대응의 상세 설명과 기록을 다시 보여 준다. 주행 중 돌봄 기록 메서드를 직접 호출해도 저장하지 않는다.

기존 Pleos 색·Asta Sans·타이포·버튼을 재사용한다. 본문·버튼은 24sp 이상, 핵심 안내는 40sp, 버튼 72dp 이상, 진입 버튼 96dp, 간격·가장자리는 24dp 이상이다. 가로는 근거와 정차/기록을 두 열, 세로는 한 열의 수동 스크롤로 제공한다. 키보드·자동 스크롤·장식 애니메이션을 추가하지 않는다.

## 상태·반복 제안 정책

`CryResponseCoordinator`는 Android와 독립적인 공용 Kotlin 상태 흐름이다.

```text
IDLE → SUGGESTED → (사용자 확인) ACTIVE → STOP_SELECTED
                   ↑ 수동 시작          │
          취소·확정 기록·돌봄 완료 확인 → IDLE
```

- 제안은 IMMINENT 항목의 종류·기준 기록·계획 범위로 식별한다. 같은 기준의 반복 tick·ETA 지연·새로고침은 같은 제안이다. 확인/취소한 기준은 다시 제안하지 않는다.
- 취소·완료 후 20분은 다른 자동 제안도 쉬지만 수동 버튼은 계속 사용할 수 있다. **제품의 알림 억제 정책이며 아기를 기다리게 해도 되는 의학적 시간은 아니다.**
- ID가 다른 오래된 확인 입력은 무시한다. 제안 근거가 사라지면 제안만 철회하며 대응을 자동 시작하지 않는다.
- 아이·외출·실제/데모 맥락을 구분한다. 맥락 변경은 기존 대응을 닫으며 최근 8개 맥락의 확인 이력을 메모리에 보관해 체험 전환이 반복 제안을 일으키지 않게 한다. 최근 기준 토큰은 맥락당 최대 64개다.
- 선택한 시설의 현재 여정·좌표·출처·접근성 증거가 바뀌거나 만료되면 선택을 해제하고 대응은 유지한다. ETA 지연은 예보와 두 정차 계획을 현재 입력으로 다시 계산한다.
- 진행과 제안 이력은 ViewModel 수명 동안 유지한다. 프로세스가 새로 시작되면 대응을 자동 재개하지 않는다. 기존 개인 돌봄/준비물 파일 이외에 울음·의료 상태의 새 저장 파일을 만들지 않는다.

`ResponseAssessor`는 현재 아이·출처가 일치하는 기록과 60초 이내의 예보 결과만 사용한다. 미래·오래된 기록, 잘못된 수면 순서, 혼합 출처는 개인 근거로 쓰지 않는다. 월령만으로 마지막 돌봄 시각이나 원인을 만들지 않는다. 착석은 차량 시동이나 속도가 아니라 보호자가 확인한 세션만 사용한다.

## 정보 부족·데모·건강 안내

시설 없음·접근성 미확인·내비 실패에서도 확인 항목·직접 정차 확인 안내·닫기와 돌봄 기록 경로를 유지한다. 길가나 갓길을 자동으로 안전한 정차 위치라고 지정하지 않는다. 후보의 존재가 현재 현장의 안전이나 개방 상태를 보증하지 않는다.

‘더 보기 → 울음 대응 체험’은 임박 예보·정차 후보 없음·내비 실패를 제공한다. 기준 시각은 체험 진입 때 고정한다. 모든 데모 기록·선택은 DEMO 출처를 유지하며 개인 파일이나 실제 내비에 전달하지 않는다. 데모 선택은 실제 등록 성공으로 표시하지 않는다.

건강 문구는 기록에 근거한 확인 안내와 의료적 판단의 경계를 표시한다. 긴급한 건강 문제가 의심되면 안전 정차와 응급 도움 요청을 우선하도록 한다. 원인 확진, 울음 확률, 수유 지시나 의료적 대기 시간을 제공하지 않는다.

근거(2026-11-12 확인): [NHS — Soothing a crying baby](https://www.nhs.uk/baby/caring-for-a-newborn/soothing-a-crying-baby/). 울음의 이유가 다양하고 항상 구분할 수 있는 것은 아니며, 평소와 다른 울음·아픈 기색·심각한 이상 징후는 의료적 평가를 우선한다는 점을 직접 요약했다. 영국 연락처를 한국 제품에 복사하지 않았다. 차량 내 동작은 [Pleos 주행 규제·주의 분산 요약](../guides/pleos-dev.md)을 따른다.

## 검증 상태

GCP의 새 임시 검증 폴더에서 공용 **179개**·서버 **9개**, 총 **188개 테스트를 통과**했다. 공용에는 상태 전이·반복 억제·기록/근거 경계·시설 선택에 대한 #8 테스트 17개가 포함된다. 실패·오류·스킵 0이다. 앱 debug·계측 APK 빌드와 설치도 통과했다.

```bash
./gradlew :shared:build :backend:build :frontend:app:assembleDebug :frontend:app:assembleDebugAndroidTest --console=plain -Pandroid.builder.sdkDownload=false -Phmg.testRunner=com.hmgchallenge.app.response.CryResponseSmokeInstrumentation
adb shell am instrument -w com.hmgchallenge.app.test/com.hmgchallenge.app.response.CryResponseSmokeInstrumentation
```

`CryResponseSmokeInstrumentation`은 실제 Android 컨트롤러와 별도 임시 폴더의 AtomicFile을 사용해 데모 기록/출처/개인 파일 격리, 데모의 실제 내비 요청 차단, 주행 기록 차단, 실제 저장 확인 후 복귀를 검증했다. 파일 쓰기는 반영됐지만 확인에 실패한 경우에도 대응이 열려 있고 저장소가 NEEDS_RELOAD가 되는 것을 확인했다. 자체 임시 폴더는 제거됐고 기존 개인 돌봄·준비물은 보존됐다.

빌드 입력 109개 파일은 현재 소스와 검증 압축본에서 일치한다. 키·환경 파일·Git·개발 로그·개인 기록은 전송하지 않았다. 소스 압축본 SHA-256: `5c15f922e9b8ecf2611f9dff5ecd4c26d9c548e2038622cd04c7332dc6c34c9b`.

debug APK SHA-256: `d615c6637d76472ccef2d002984f9164cd2750b5a09a3822126c8e7f27f9b747`. 설치된 APK와 일치한다.

화면 PNG 20개와 UI 계층 XML을 확인했다. 공식 기기 프로필 2560×1440·160dpi, 강제 크기/밀도 변경 없이 실제 앱 창 1682×1210dp(가로)·841×1210dp(세로)에서 검증했다.

- 수동 진입·Back으로 닫기, 임박 제안 확인·‘나중에’ 뒤 반복 없음, 풀케어/가까운 정차 선택, 수유 기록 후 복귀·기록 없이 완료 확인을 터치로 재현했다.
- 첫날에는 개인 계획 시각을 만들지 않았다. 시설 없음·내비 실패에도 확인 안내·기록/닫기 경로가 유지됐다. 데모 선택에는 실제 내비 추가 버튼이 나타나지 않았다.
- 두 창 크기·주간/야간의 글자·간격·대비를 확인했다. 기존 #7과 동일한 글자/카드/버튼 색 조합으로 대비 4.5:1 이상을 유지한다. 두 너비의 정차 선택 버튼은 64×72dp 이상, 서로 간격과 가장자리 24dp 이상이었다.
- 세로·야간에서 Virtual Console로 D·10km/h를 적용했다. 상세 근거와 돌봄 기록 버튼이 사라지고 요약·두 정차 선택만 유지됐다. 가까운 정차를 선택한 상태도 확인했다. P·속도 0으로 되돌리면 상세 설명이 다시 나타났다.
- 기존 개인 돌봄 기록은 설치 전부터 전체 화면 검증 종료까지 SHA-256이 같았다. 준비물 파일도 시작 전 상태(없음)를 유지했다. 기기 검증용 임시 폴더는 제거됐다.

검증 종료 후 P·속도 0과 원래 야간 모드로 복원하고, 데모를 종료한 실제 첫 화면으로 남겼다. 빌드 로그·테스트 XML·기기 컨트롤러 결과·원본 PNG/XML·최종 요약은 Git에서 제외한 `.dev/verification/issue8/2026-11-12/`에 보관한다. 커밋 전 소스이므로 위 지문으로 검증 입력을 식별한다.

현재 실제 경로 접근성 공급자와 경유지 등록 성공 검증은 #5·#6의 남은 범위다. #8은 출처가 표시된 데모 정차와 실제 정보 부족 상태로 동선을 검증했으며 실제 등록 성공으로 계산하지 않는다.
