# 시설 데이터와 정차 계획 (#6)

확인일: 2026-11-12. 시설 존재 정보와 현재 여정의 접근 가능성은 서로 다른 데이터다. 시설 좌표·도로 이름만으로 진행 방향, 실제 진입 가능 여부, 주행 시간이나 마지막 휴게소를 만들지 않는다.

## 공개 데이터와 이용 조건

공공데이터포털의 공식 다운로드 UI로 받은 JSON에서 필요한 시설 필드만 정규화했다. 두 표준데이터 페이지의 기관별 상세 창에서 제공기관 **한국도로공사**, **무료**, **이용허락범위 제한 없음**을 확인했다. 공공누리 유형은 원문에서 확인하지 못해 별도 유형을 지정하지 않았다. 앱과 응답 메타데이터에 기관·데이터셋·출처 URL을 남긴다.

| 항목 | 휴게소 | 졸음쉼터 |
| --- | --- | --- |
| 공식 출처 | [전국휴게소정보표준데이터](https://www.data.go.kr/data/15025446/standard.do) | [전국졸음쉼터표준데이터](https://www.data.go.kr/data/15028203/standard.do) |
| 기관별 데이터 | 한국도로공사_휴게소정보 | 한국도로공사_졸음쉼터 |
| 포털 수정일 | 2026-09-21 | 2026-03-05 |
| 행의 데이터기준일자 | 2026-09-17 | 2026-02-25 |
| 갱신 주기 | 반기 | 연간 |
| 받은 행 수 | 215 | 253 |
| 방향 필드 | 상행·하행·양방향·빈 값 | 기점·종점 문자열 |
| 수유실 필드 | `수유실유무`: Y 212건, N 3건 | 필드 없음 |
| 기저귀 교환대 | 필드 없음 | 필드 없음 |

방향 표기는 원문 그대로 보존한다. 빈 방향을 휴게소 이름의 괄호나 좌표로 채우지 않는다. 수유실은 명시적인 Y만 AVAILABLE, N만 UNAVAILABLE로 변환하며 빈 값·알 수 없는 값은 UNKNOWN이다. 졸음쉼터의 기타 편의시설 문자열로 수유실을 추정하지 않는다. 기저귀 교환대는 모두 UNKNOWN이다.

원문에는 빈 값의 일반적인 의미가 정의되어 있지 않았다. 휴게소 데이터는 졸음쉼터·임시휴게소를 포함하지 않는다. 전국 도로의 모든 시설을 망라하거나 현재 영업·수유실 운영 상태를 보장하는 자료가 아니다. `verifiedAtEpochMillis`는 현장 방문 시각이 아니라 행에 적힌 **데이터기준일자(한국 시간 00:00)**다.

번들 `backend/src/main/resources/facilities/public-catalog.json`에는 시설명·유형·좌표·노선번호/이름·방향·수유실·기준일·출처만 둔다. 전화번호·담당자·주소·음식점·기관 연락처는 저장하지 않는다. 원본 파일은 Git에 넣지 않는다. 데이터셋의 `fetchedAtEpochMillis`는 2026-11-12에 실제 받은 시각이며 API 요청 때 새로 쓰지 않는다.

## API와 갱신

```bash
curl http://localhost:8081/api/facilities
curl 'http://localhost:8081/api/facilities?mode=demo'
```

응답은 `DataSnapshot<FacilityCatalog>`다. 기본 모드는 PUBLIC_DATA이며 데모로 자동 대체하지 않는다. `mode=demo`를 명시한 요청만 합성 시설을 돌려준다. 다른 모드는 HTTP 400이다. 시설 전체 목록을 제공하므로 아기 기록·현재 위치·목적지를 서버에 보내지 않는다. 최대 5,000건·JSON 2MB로 제한한다.

- 파일 없음: UNSUPPORTED, 잘못된 파일: FAILED, 자료 기준일이 오래됨: STALE.
- 공식 페이지의 JSON 다운로드에는 로그인·서비스키가 필요하지 않았다. 고정 다운로드 API는 문서화되어 있지 않아 비공개 경로를 주기적으로 호출하지 않는다.
- 갱신하려면 두 페이지에서 새 JSON을 받아 아래의 Kotlin 정규화기를 실행한다. 잘못된 좌표·누락/미래 기준일·중복 행이 있으면 발행을 중단한다. 잘못된 행을 조용히 버린 부분 자료를 운영 파일로 만들지 않는다.

```bash
./gradlew :backend:importFacilities \
  -PfacilityRestFile=/absolute/path/rest.json \
  -PfacilityShelterFile=/absolute/path/shelter.json \
  -PfacilityOutput=/absolute/path/public-catalog.json
```

이미 내려받은 입력을 재현할 때만 `-PfacilityFetchedAtEpochMillis=실제_다운로드_밀리초`를 지정할 수 있다. 기준일을 현재 시각으로 바꾸지는 않는다. `HMG_FACILITY_CATALOG=file:/absolute/path/public-catalog.json`으로 정규화 파일을 지정하고 서버를 재시작한다. 설정하지 않으면 번들을 읽는다. 자동 수집·운영 배포는 포함하지 않았다.

## 경로 근거와 두 정차 계획

`RouteFacilityEvidence`는 현재 `journeyId`, 시설별 접근성, **실제 경로상의** 시간(초)·거리(미터), 내비 요청용 진입 좌표를 제공하는 어댑터 경계다. 출처는 NAVI_SDK 또는 명시적인 DEMO만 허용한다. 공공시설 중심 좌표를 내비 진입 좌표로 자동 대입하지 않는다.

`StopPlanner`는 다음 조건을 모두 만족하는 시설만 후보로 만든다.

1. 여정·접근 근거가 READY이고 관측 후 60초 미만이며 여정 ID와 출처가 일치한다.
2. 시설 목록의 출처가 실경로/데모와 맞고, 캐시 조회 후 24시간 미만이다.
3. 시설 기준일이 휴게소 200일, 졸음쉼터 400일 미만이다. 반기/연간 갱신을 고려한 제품 정책이며 공식 영업 보증 기간이 아니다.
4. 접근이 CONFIRMED_ON_ROUTE이고 진입 좌표·시간·거리가 있으며, 현재 지점 이후이자 목적지 이전이다. UNKNOWN·반대 방향·진입 불가는 제외한다.

풀케어는 그중 수유실 AVAILABLE인 후보를, 가까운 정차는 수유실 유무와 관계없이 휴게소·졸음쉼터 후보를 주행 시간순으로 정렬한다. 후보 없음은 정상 결과다. 기저귀 교환 가능 여부를 수유실에서 유추하지 않는다.

현재 NaviHelper 어댑터는 ETA·목적지를 제공하지만 남은 경로 전체·진행 방향별 시설 접근성 근거는 제공하지 않는다. 따라서 **실제 여정에서는 접근성 미확인**을 표시하고 추천·마지막 휴게소·경유지 요청을 활성화하지 않는다. 실제 경로 공급자를 연결하지 않은 상태에서 이 기능을 실도로 추천 완료로 계산하지 않는다.

후보는 기존 #5의 `StopCandidate`를 사용한다. 진입 좌표·여정 ID·접근 확인 시각을 포함하며, 실제 내비 요청 직전과 확인 후 재조회에서 여정 일치·60초 만료를 다시 확인한다. 2026-11-13부터 공급자의 선택적 `navigationPoiId`를 `FacilityApproach` → 후보 → 요청·결과 확인까지 보존한다. 현재 Pleos 어댑터는 ID가 없으면 전송 전에 차단하며 공공시설 행 ID를 내비 ID로 사용하지 않는다. ID가 있어도 경로 접근 근거나 진입 좌표 검증을 대신하지 않는다. 내비 슬롯 보존·명시적 확인·결과 읽기 규칙은 [내비 연동](navigation.md)을 따른다. DEMO는 실제 SDK 요청에 전달하지 않는다.

## 마지막 휴게소·캐시·화면

- 경로 공급자가 **남은 모든 휴게소를 확인했다**고 명시한 경우만 경로 거리상 가장 뒤의 이용 가능 휴게소를 고른다. 불완전한 범위·미확인 접근·누락/오래된 휴게소가 있으면 ‘마지막’을 확정하지 않는다. 확인된 구간에 휴게소가 없을 때는 없음으로 표시한다.
- 마지막 휴게소까지 1~600초일 때 앱 안의 정적 배너를 한 번 제공한다. 여정 ID+시설 ID로 ViewModel 수명 동안 중복을 막는다. 회전·창 변경·동일 ETA 갱신·확인 버튼 뒤에는 반복하지 않는다. 새 여정은 다시 알릴 수 있다. 프로세스 재시작 뒤의 영구 중복 방지는 아직 범위에 포함하지 않았다.
- 앱은 전체 목록을 비공개 AtomicFile 캐시에 저장한다. 캐시 24시간은 **앱이 HTTP 응답을 받은 기기 시각**으로 센다. 서버 시계와의 차이로 정상 응답을 거부하지 않으며 시설별 기준일·데이터셋 다운로드 시각은 보존한다. 통신 실패 시 마지막 목록과 받은 날짜는 표시하지만 STALE로 바꾸어 정차 판단에서는 제외한다. 손상된 캐시는 새 서버 응답으로 복구하며 저장 실패는 알리고 현재 네트워크 결과를 유지한다.
- 연결 화면에 오프라인·시설 없음·오래된 자료·접근성 미확인과 차량 내비에서 확인할 대체 안내를 제공한다. 기존 기록 화면 정책에 따라 주행이 시작되면 연결 화면을 닫고 기록 홈으로 돌아가 데모 설정을 숨긴다. 주차해도 설정 화면으로 자동 복귀하지 않는다. 시설 컴포넌트 자체도 제한 중 상세를 줄이고 데모 변경을 막는다. 주행용 핵심 정차 화면은 #8에서 연결한다. 자동 스크롤·소리·팝업·자동 내비 변경은 없다.
- 주차 후 ‘고정 경로 데모 보기’로 합성 시나리오를 실행한다. 가까운 졸음쉼터(3분), 수유실 휴게소(6분), 마지막 휴게소(8분)를 서로 구분한다. 더 가까운 반대 방향·진입 불가 시설은 제외한다. 데모 표시는 유지하고 실제 내비 요청 버튼은 제공하지 않는다.

F2 출발 화면·F4 울음 대응의 최종 디자인과 동선은 #7·#8 범위다. 현재 연결 화면은 데이터·실패·고정 경로를 확인하는 구현이다.

## 검증

GCP Pleos AVD에서 다음을 실제 실행했다. 로컬에는 JDK·Android SDK가 없다.

- `./gradlew :shared:build :backend:build :frontend:app:assembleDebug :frontend:app:assembleDebugAndroidTest --console=plain -Pandroid.builder.sdkDownload=false`: **공용 137개 + 서버 9개 = 146개 통과**, 실패·오류·스킵 0. 시설 계획 19개, 캐시 9개, 서버 시설 8개와 기존 내비 회귀를 포함한다. 반대 방향·진입 불가·불완전한 범위·오래된 기준일·빈 후보·서버 시계 차이를 검사했다.
- 공개 원본에서 연락처 등을 제거한 입력 468건을 `:backend:importFacilities`로 다시 정규화했다. 제외 행 0건이며 번들과 **바이트 단위 일치**했다. 데이터 SHA-256: `7b0b7c185795f9ff978964c9b7c5b2a3b30369b247db36cbe5e7a181c5318f3f`.
- 실제 HTTP API에서 PUBLIC_DATA 468건·명시적 DEMO 분리·잘못된 모드 HTTP 400을 확인했다. 빈 목록과 STALE 응답은 임시 검증 파일로 만들고 운영 번들을 수정하지 않았다.
- 최종 APK를 설치해 2560×1440·160dpi의 가로 1682×1210dp / 세로 841×1210dp와 주간·야간을 캡처했다. 두 정차 계획·마지막 휴게소·배너 확인 후 중복 방지·72dp 동작 버튼을 확인했다. 기존 테마의 4.5:1 이상 대비 토큰과 24sp 이상 본문을 재사용한다.
- 시설 없음·오래된 응답·네트워크 종료 후 캐시 복원을 실제 화면에서 확인했다. 마지막 PUBLIC_DATA 468건 캐시와 기존 돌봄 기록은 보존했다. 가상 주행 시작 시 연결 화면이 닫히고 설정이 숨겨졌으며, 종료 후 P·속도 0·DO=false·야간 모드 no로 복원했다. 임시 서버는 종료했다.
- 최신 소스·빌드 입력 **91개 파일**이 전송 압축본과 일치한다. 소스 SHA-256: `91c155c26ed28d71f9ac97227bce8076384c5cfcbfa025229872ea8a9c28a30f`. 설치 APK SHA-256: `c91d3e9f3a6b40befb66a25f53af90458e787df54444393dcb2001afe1a278d3`.

**실제 경로 접근성 공급자 연결과 실제 시설 경유지 등록은 여전히 미완료다.** 확인한 SDK 공개 표면은 현재 경로 전체·방향별 시설 접근성을 제공하지 않으며, 이 작업 환경에 구성된 외부 경로 공급자도 없었다. 공개 데이터/API·순수 판단·데모·캐시 검증을 실도로 추천 완료로 표시하지 않는다. #6은 이 범위가 남은 부분 완료 상태다.
