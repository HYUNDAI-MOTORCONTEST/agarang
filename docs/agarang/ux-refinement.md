# 조작과 상태를 중심으로 정리한 UI/UX

작업일: 2026-11-13. 텍스트를 읽는 부담을 줄이고, 현재 상태와 다음 행동을 구분하는 후속 개선이다. 판단 엔진·돌봄 기록 형식·SDK 권한은 변경하지 않았다.

## 바꾼 동선

- **출발 준비:** 프로필이 없으면 같은 ‘미확인’ 값을 반복하는 대신 설정 진입을 먼저 보인다. 예보가 있으면 수유 예상 범위·도착·근거의 출처를 유지하고 긴 설명은 펼쳐 본다. 출발 선택은 아이콘이 있는 큰 카드로 표현하며, 확인 후 저장된 계획에 체크와 선택 상태가 남는다. 선택한 카드도 다시 검토할 수 있는 버튼이다.
- **홈 준비물:** 수유용품·기저귀를 홈에서 바로 체크·해제할 수 있다. 진행 막대는 실제 확인한 항목 수만 나타내며, 아기 상태나 안전한 출발을 보증하는 표시가 아니다. 수량을 계산할 수 없으면 ‘수량 확인 필요’를 유지한다.
- **준비물 목록:** 체크가 기본 조작이다. 삭제·기본 항목 복원은 ‘목록 편집’에서만 드러내어 확인 중 잘못 누르는 것을 줄인다. 계산 근거를 접어도 수량·외출 범위가 미확인인 이유는 숨기지 않는다.
- **울음 대응:** 가까운 정차를 먼저 보여 주고 시설명·예상 소요 시간과 선택 표시를 같은 카드에 묶었다. 기록 근거는 정차 중 펼쳐 본다. 원인을 진단하지 않는다는 안내·정보 부족·내비 결과 미확인 표시는 유지한다. 실제 내비 변경의 별도 확인·슬롯 보존·재조회 절차도 유지한다.
- **주행 중:** 준비물·설정·기록 입력과 비활성 기록 버튼 묶음을 숨긴다. 도착·수유 요약과 울음 대응·정차 선택을 남기며, 대응 화면의 고정된 상단 ‘이전’으로 스크롤 없이 복귀한다. 입력 중 주행으로 바뀌면 기존 화면 초기화·키보드 닫기 정책을 따른다. 데모·주행 제한·상태 미확인을 구분한다.

## 시각·접근성 기준

- 자체 제작한 정적 선 아이콘을 Pleos 48dp 그리드로 그린다. 글자 라벨을 함께 쓰며 새 외부 이미지·라이브러리·음원은 추가하지 않았다.
- 예보 카드의 섹션 제목에는 상태 막대와 텍스트만 둔다. 젖병·위치 아이콘은 수유·도착 정보의 구분에 쓰고, 제목에 같은 모양을 반복하지 않는다.
- 본문·버튼은 24sp 이상, 주요 제목·수치는 32sp 이상이다. 터치 최소 64dp, 기본 버튼 72dp, 동작 카드 최소 112dp를 토큰으로 지정한다. 화면 가장자리와 조작 사이 간격은 24dp 기준이다.
- 누름·선택·체크 상태를 즉시 구분한다. 장식 애니메이션·자동 스크롤·새로운 소리는 추가하지 않았다. 단일 선택과 펼치기/편집 버튼의 접근성 역할도 구분한다.
- 실제 사용한 12개 글자·아이콘/배경 조합을 알파 합성 후 계산했다. 주간·야간·선택·누름·비활성 포함 최저 5.0:1이다. 체크 모양과 라벨을 함께 써 색만으로 상태를 전달하지 않는다.
- 근거: [차량 UI 요약](../guides/pleos-ui.md), [컴포넌트·상호작용 요약](../guides/pleos-components.md), [주행 제한](../guides/pleos-dev.md). 간격·터치 최소값은 이 가이드에 명시한 Google 차량 품질 기준의 보조 적용이다.

## 검증

- GCP Pleos 에뮬레이터(2560×1440·160dpi)에서 앱 debug·계측 APK 빌드, 공용 195개·서버 12개 총 207개 회귀 테스트를 확인했다.
- 내비 읽기 전용·출발·울음 대응·시나리오 통합의 기기 계측 4종이 통과했다. 이번 통합 계측의 라이브 HTTP 옵션은 지정하지 않아 해당 항목은 미실행이다. 실제 내비 경로를 만들거나 바꾸지 않았다.
- 실제 `MainActivity`의 데모에서 홈 체크/해제·확인 개수, 저장된 출발 계획 표시, 편집 전 삭제 숨김·편집 종료, 정차 선택 표시, 근거 펼치기와 홈 복귀를 확인했다.
- 1682×1210dp / 841×1210dp 창의 주간·야간을 캡처했다. 좁은 창의 아래쪽 준비물까지 수동 스크롤로 접근했다. 창 크기는 기존 헤드리스 환경과 같이 `am task resize`로 전환했으며 공식 FormFactorConsole·실차·release APK 검증은 포함하지 않는다.

- 공식 Virtual Console의 D 전환으로 실제 `DO: true / UxR: 80`을 확인했다. 입력창·키보드·준비물/기록/편집 조작이 사라졌고, 두 창 크기의 주행 홈과 정차 선택·고정 상단 ‘이전’ 복귀를 실제 터치로 확인했다. 속도는 최고 16km/h 이후 자연 감속해 D·0km/h 구간을 포함했다. 일정 속도를 유지한 주행이나 실도로 시험으로 확대하지 않는다.
- P·속도 0 복원 뒤 이전 입력창이 다시 열리지 않았다. 데모 종료·원래 넓은 창·주간 모드·`DO: false / UxR: 0`·내비 `EMPTY / SAFE_GUIDING`을 재확인했다. 최초에 없던 개인 돌봄·준비물 파일은 종료 후에도 없었으며 실제 내비 경로를 변경하지 않았다.
- 최종 설치 APK와 빌드 출력의 지문, 현재 소스·빌드 입력 117개 파일과 전송 압축본의 내용을 대조했다. 로컬에는 JDK·Android SDK가 없어 실행 검증은 GCP 결과다.

## 예보 제목 아이콘 중복 정리

같은 카드의 제목과 수유 항목에 젖병을 반복하던 부분을 제거했다. 첫 사용 화면에도 같은 기준을 적용하며, 제목의 상태 막대와 수유·도착 정보 및 조작 버튼의 아이콘은 유지한다.

- `:frontend:app:assembleDebug`를 기존 GCP 검증 환경의 새 임시 폴더에서 통과했다. 단순 표시 제거이므로 공용·서버 테스트와 주행 전환 계측은 다시 실행하지 않았다.
- 수정 APK를 설치하고 1682×1210dp·841×1210dp 창의 주간·야간, 준비물 2/5와 저장한 출발 선택, 첫 사용 화면을 다시 캡처했다. 캡처 7장을 직접 열어 제목·수유·도착 정보가 잘리거나 겹치지 않는 것을 확인했다. 색·타입·아이콘·터치 토큰은 그대로여서 앞선 대비 계산을 유지한다.
- 데모에서만 조작했으며 개인 기록 파일 상태, 원래 창 크기와 테마, 주차 제한 해제 상태를 복원했다. 설치 APK 지문과 빌드 결과가 같고, 현재 소스·빌드 입력 117개 파일도 검증 압축본과 같다.
- 자료는 `.dev/verification/icon/2026-11-13/`에 둔다. 드라이브의 홈 캡처 7장을 갱신하며, 변경 없는 입력·주행 캡처는 이전 검증본을 유지하고 이미지마다 빌드 지문을 기록한다.
