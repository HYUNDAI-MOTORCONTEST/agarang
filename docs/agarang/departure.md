# 출발 예보·출발 선택·준비물 (#7)

구현 기준: 이슈 #7, 예보 엔진 #4, 내비·시설 계약 #5·#6. 확인일 2026-11-12.

## 화면과 흐름

제출 앱의 첫 화면을 `DepartureApp`으로 연결했다. 출발 예보와 도착 예정, 출발 선택, 준비물 요약, 바로 돌봄 기록을 제공한다. 기존 프로필·돌봄 기록·연결 상태 화면은 하위 동선으로 유지한다.

- 가로(window 2개)는 예보·기록과 출발 선택·준비물을 두 열로 배치한다. 세로(window 1개)는 한 열에서 예보·출발 선택을 우선하고 준비물·기록은 고정된 하단 메뉴로 바로 연다.
- 다음 수유의 예상 시각/범위·개인 설정/이력/일반 참고·도착 예정·정보 부족을 함께 표시한다. 월령만 있거나 최근 기록이 오래되면 개인 수유 시각을 만들지 않는다. 준비물 기본 목록은 기록 0건에서도 사용할 수 있다.
- **지금 출발:** 예보·준비물 확인 후 계획을 저장한다. ‘방금 아기가 카시트에 앉았어요’를 명시적으로 선택한 경우에만 현재 시각을 착석 시작으로 기록한다. 차량 시동·속도로 아기 착석을 추정하지 않는다. ‘착석 세션 종료’·‘새 외출 준비’로 종료/초기화할 수 있다.
- **돌봄 후 출발:** 실제 돌봄을 마친 뒤 기록하고 예보를 다시 확인한다. 대기 시간을 임의로 만들거나 돌봄을 했다는 이유로 ETA를 더하지 않는다. 출발 계획을 저장하며 내비의 최신 도착 예정은 별도로 다시 확인하도록 안내한다.
- **중간 정차 계획:** #6의 풀케어·가까운 정차·마지막 휴게소를 소비한다. 데모 시설 선택은 데모 계획에만 저장한다. 접근성이 확인되지 않은 실제 여정은 시설 확인이 필요한 계획으로 표시한다. 실제 내비 등록을 완료했다고 표시하지 않는다.

예보 기준 설정과 준비물 계산 기준은 별도다. 보호자가 확인한 수유·깨어 있는 시간·휴식 간격을 저장하면 기존 돌봄 기록·프로필 ID·선호 수량을 보존한다. 준비물 계산에 쓴 간격이나 예비 수량을 개인 돌봄 예보에 자동 복사하지 않는다.

## 준비물 수량·외출 범위

`DeparturePlanner`는 다음 계산을 Android·네트워크와 독립적으로 수행한다.

| 항목 | 계산·누락 처리 |
| --- | --- |
| 편도 이동 | 최신 내비 ETA까지의 남은 시간. 내비가 없을 때만 보호자가 직접 확인한 이동 시간을 사용 |
| 전체 외출 | 편도 이동 + 보호자가 입력한 체류·귀가 추가 시간. 자동으로 왕복 2배를 가정하지 않으며 추가 시간이 0이면 미확인 |
| 수유 준비 | 올림(외출 범위 / 확인한 준비물용 수유 간격) + 예비 회분 |
| 기저귀 준비 | 올림(외출 범위 / 확인한 준비물용 기저귀 간격) + 예비 개수 |
| 간격/시간 미설정 | 해당 수량은 null·‘확인 필요’. 월령별 기본 간격이나 가짜 기록으로 채우지 않음 |

간격은 수유 지시·기저귀 교체 처방이 아닌 **준비물 계산용 보호자 입력**이다. 수유 회분은 mL·섭취량 권장이 아니다. 예비 기본값 1회분·2개는 수정 가능한 제품 준비물 기본값이며 의학적 수치가 아니다. 선택 가능한 간격·최대 72시간 외출 범위도 제품 입력 범위다.

계산은 밀리초 범위에서 먼저 올림하므로 120분+1ms를 120분으로 버리지 않는다. UI에 보이는 분도 올림해서 표시한다. 내비 관측 60초 만료·미래 관측·ETA 과거·잘못된 출처·지나치게 긴 여정은 사용하지 않는다. 직접 설정한 시간은 준비물 범위이며 실제 내비 ETA로 표시하지 않는다.

## 저장·체크·데모 분리

- 설정·기본/추가 준비물·체크 상태·출발 선택·확인한 착석 세션은 비공개 `files/departure.json`에 저장한다. 기존 `care-record.json`과 별도이며 서버로 보내지 않는다. 스키마 1, 최대 30개 항목·이름 30자·64KB 읽기 한도를 둔다.
- AtomicFile 쓰기 후 다시 읽어 일치한 상태만 화면에 확정한다. 손상/미지원 파일·불확실한 쓰기는 NEEDS_RELOAD로 두고 덮어쓰지 않는다. IO는 메인 스레드 밖에서 수행하며 겹친 입력은 큐에 쌓지 않는다.
- 체크는 외출 ID·아이·목적지·편도/전체 범위에 묶인다. 좌표와 이름이 확인된 같은 목적지의 SDK 세션 ID만 바뀌면 체크를 유지한다. 목적지·아이·외출·범위가 바뀌거나 24시간이 지나거나 시계가 뒤로 가면 다시 확인한다.
- ETA가 늘어 필요한 수량이 증가하면 기존에 체크한 수량이 부족한 항목만 미확인으로 바꿔 보인다. 물티슈처럼 개수 계산과 무관한 항목은 같은 외출 범위에서 유지한다. 필요한 수량이 줄어도 이미 확인한 더 많은 수량을 취소하지 않는다.
- 새 외출은 체크·출발 선택·착석 세션을 초기화하고 목록·계산 기준·개인 돌봄 기록은 보존한다. 등록/삭제와 기본 준비물 추가도 제공한다.
- ‘더 보기 → 출발 준비 체험’에서 기록 있는 여정·기록 없는 첫날·도착 90분 지연을 선택한다. 데모의 기준 시각은 진입 때 고정하며 타이머가 돌 때 마지막 수유를 새로 만들지 않는다. 데모 기록·프로필·준비물 수정은 메모리에만 반영하며 실제 개인 파일과 실제 내비로 전달하지 않는다. 데모 표시는 화면과 시설명에 유지한다.
- 데모의 기록·수정·취소는 공용 기록 검증에 DEMO 출처를 명시해 수행하며 출처를 CAREGIVER로 바꾸지 않는다. 실제 저장 코덱과 저장소의 기본 검증은 계속 CAREGIVER만 허용한다. 선호 수량을 고른 경우 데모 수유 기록에도 그 수량을 보존한다.

## 차량 UI·주행 제한

Pleos 색·Asta Sans·타이포 토큰을 재사용했다. 핵심 제목 40~48sp, 주요 값 32sp 이상, 본문·버튼 24sp 이상, 버튼 72dp 이상, 체크 행 96dp·아이콘 48dp, 터치 대상 간격과 가장자리 24dp 이상을 사용한다. 글자 크기를 줄여 한 화면에 억지로 넣지 않고 세로에서는 우선순위와 수동 스크롤로 대응한다.

주간/야간 대비 계산(알파 글자는 배경 합성 후 WCAG 상대 휘도 계산): 본문/흰 카드 18.42/16.67, 보조 글자/흰 카드 11.39/12.04, 보조 글자/화면 배경 10.88/12.04, 체크 표시 18.42/16.67이다. 기존 버튼 토큰의 최소 대비는 disabled 4.98/5.60이다. 파란 장식 막대는 같은 뜻의 글자가 있는 보조 표시이며 글자색으로 쓰지 않는다.

CarUxRestrictions의 DO·NO_SETUP·NO_KEYBOARD 중 하나가 제한되면 상세 화면·설정을 닫고 최소 요약과 빠른 기록으로 전환한다. 주행 상태 소스를 모르면 ‘주행 상태 미확인’으로 표시하며 주행 중이라고 단정하지 않는다. 저장 직전에도 제한을 재확인한다. 주차 후에는 입력 화면으로 자동 복귀하지 않는다.

준비물 이름 입력 화면만 IME에 맞춰 크기를 조정하고, 다른 화면은 다른 window의 키보드 때문에 밀리지 않도록 한다. 주행 전환/입력 화면 이탈 시 포커스를 강제로 해제하고 키보드 숨김을 요청한다. 숨김은 시스템의 best-effort API이므로 실제 화면에서도 확인한다. 근거: [Compose 포커스 해제](https://developer.android.com/develop/ui/compose/touch-input/focus/move-focus), [SoftwareKeyboardController](https://developer.android.com/reference/kotlin/androidx/compose/ui/platform/SoftwareKeyboardController). Pleos 정책은 [플랫폼 요약 10장](../guides/pleos-platform.md)을 우선한다.

새 차량 권한·오디오·자동 스크롤·애니메이션·자동 내비 변경을 추가하지 않았다. Back은 하위 화면에서 이전 단계, 최상위에서 `moveTaskToBack(true)`를 유지한다.

## 검증 (2026-11-12)

로컬에는 JDK·Android SDK가 없어 승인된 기존 GCP 테스트 VM의 새 임시 폴더에서 검증했다. 앱·공용·서버·공개 시설 데이터 등 빌드 입력 105개 파일이 현재 소스와 검증 압축본에서 일치한다. 키·환경 파일·Git·개발 로그는 전송하지 않았다.

```bash
./gradlew :shared:build :backend:build :frontend:app:assembleDebug :frontend:app:assembleDebugAndroidTest --console=plain -Pandroid.builder.sdkDownload=false -Phmg.testRunner=com.hmgchallenge.app.departure.DepartureSmokeInstrumentation
```

- 공용 **162개** + 서버 **9개** = **171개 테스트 통과**, 실패·오류·스킵 0. 수량 경계 1ms·내비 만료·외출 범위·목적지/아이 변경·체크 유효 기간·데모 출처 분리·저장 실패·주행 직전 쓰기 차단을 포함한다.
- 최신 debug APK·계측 APK 빌드와 설치 통과. `DepartureSmokeInstrumentation`이 실제 AtomicFile로 저장·재로딩·손상 파일·주행 쓰기 차단을 확인하고 자체 임시 데이터를 제거했다.
- 공식 기기 프로필 2560×1440·160dpi, 화면 크기/밀도 강제 변경 없이 실제 앱 창 1682×1210dp(가로)·841×1210dp(세로)의 주간/야간을 캡처했다. 두 너비에서 핵심 출발 버튼 3개의 터치 크기와 24dp 간격·가장자리를 확인했다. 화면 PNG 31개(키보드 진단 4개 포함)와 UI 계층 XML을 보관했다.
- 지금 출발(보호자 확인 착석 포함)·돌봄 기록/취소 후 출발·데모 중간 정차 선택을 터치로 수행했다. 도착 90분 지연 때 수유용품 2→3회분·기저귀 3→4개로 바뀌고, 부족해진 항목만 체크가 해제됐다. 전체 외출은 체류·귀가 시간이 없으면 미확인으로 유지됐다.
- 기록 없는 첫날과 수유 1건만 있는 경우 개인 수유 시각을 만들지 않았다. 실제 내비 미확인·접근성 미확인 시설은 실패 상태와 확인 경로를 표시했다.
- 준비물 추가, 입력 중 D·10km/h 전환, 입력 화면·초안 제거, 요약 전환과 키보드 닫힘을 확인했다. IME의 `mIsInputViewShown`은 닫힌 뒤에도 true로 남아 검사에서 제외했다. 화면과 `mInputShown=false`·`mInputViewStarted=false`로 실제 종료를 확인했다.
- 실제 준비물 체크가 앱 강제 종료·재실행 뒤 유지되는 것을 확인했다. 검증 전에 준비물 파일이 없음을 확인한 뒤 임시 체크만 만들었고, 검증 후 해당 파일을 제거했다. 기존 돌봄 기록의 SHA-256은 설치 전부터 전체 검증 종료까지 동일했다. 데모는 실제 개인 파일을 변경하지 않았다.

debug APK SHA-256: `07091b4e40bfe200152ba89efd9660fc37b36db64a10de5718d5bda8af779c11`. 설치된 APK와 일치한다.

빌드 로그·테스트 XML·기기 저장 결과·화면 PNG/XML·최종 요약은 Git에서 제외한 `.dev/verification/issue7/2026-11-12/`에 보관한다. 커밋 전 소스이므로 위 지문으로 검증 입력을 식별한다.

검증 종료 후 차량을 P·속도 0으로 복원하고, 야간 모드·키보드 표시 설정을 시작 전 값으로 되돌렸다. 앱은 데모를 종료한 실제 첫 화면으로 남겼다.

실제 NaviHelper 응답 회복·경로 접근성 공급자·실제 경유지 등록은 #5·#6의 남은 범위다. 데모 정차 선택을 실제 경유지 등록 성공으로 계산하지 않는다. 출발 선택과 체크리스트의 구현 완료와 전체 제출 준비 완료도 구분한다.
