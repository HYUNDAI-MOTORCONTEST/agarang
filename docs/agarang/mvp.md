# 아가랑 P0 구현 범위와 데이터 계약

기준: 제공된 아가랑 기획안(2026-10-23), GitHub 이슈 #1~#14. 작성·기술 확인: 2026-11-10.

## 첫 구현 범위

첫 동선은 **최소 프로필·기록 입력 → 아기 상태 예보 → F2 출발 코칭 → F4 울음 대응·정차 판단**이다.
기록은 판단 엔진의 입력이고, 시설 추천은 정차 판단의 한 부품이다. 전체 기록 앱이나 미디어 앱을 먼저 만드는 순서로 확장하지 않는다.

| 단계 | 범위 | 이슈 | 완료 판단 |
| --- | --- | --- | --- |
| 기반 | SDK/권한 매트릭스, 출처·단위·실패 계약, 합성 시나리오 | #2 | 이 문서·매트릭스·공용 DTO 및 계약 테스트 |
| 최소 입력 | 월령·보호자 설정, 수유·기저귀·수면 기록, 저장·취소 | #3 | 제출 앱에서 기록·복원·잘못 누른 기록 취소 |
| 판단 | 근거와 정보 부족을 표시하는 예보 | #4 | 시계·기록·여정을 고정한 규칙 테스트, 첫날 제한 모델 |
| 경로·시설 | ETA 어댑터, 케어 시설 조회·접근성, 두 단계 정차 | #5, #6 | 실제/데모 공급자 구분, 접근 가능한 후보와 실패 처리 |
| 핵심 화면 | 출발 예보·체크리스트, 울음 대응과 정차 확인 | #7, #8 | 운전자 단독 시나리오와 한 번 확인 흐름 |
| 검증·제출 | 시나리오 A/B/C, 주행·폼팩터, 실행 가능한 APK·자료 | #12, #13 | 실제 실행 커밋과 재현 가능한 검증 증거 |

F3 케어 코칭·오디오와 F5 회고는 다음 단계(#9~#11), 음성 기록/확인은 승인 후 확장(#14)이다.
앱에 없는 기능을 완료로 간주하지 않는다. 계약과 합성 데이터가 준비됐다는 것과 본 앱의 기능 완성은 별도로 기록한다.

## 앱과 서버의 경계

- `shared`: Android·Pleos SDK에 의존하지 않는 공용 계약과 순수 판단 코드. Kotlin JVM + kotlinx.serialization.
- `frontend/app`: 프로필·기록의 로컬 저장, SDK 어댑터, 주행 제한과 UI. SDK 콜백을 `StateFlow<DataSnapshot<T>>`로 변환한다.
- `backend`: 시설 데이터의 수집·정규화·조회 등 부가 기능. 기본 기록·예보를 서버 연결에 종속시키지 않는다.
- `frontend/sandbox`: 기존 시도와 비교할 실험 앱. 제출 앱으로 빌드하거나 제출 기능 완료로 계산하지 않는다.

실시간 차량 제어·아기 센서 감지·음성 승인을 전제로 핵심 흐름을 만들지 않는다. VIN도 식별자로 사용하지 않는다.

## 공용 계약 v1

실제 선언은 `shared/src/main/kotlin/com/hmgchallenge/shared/` 아래에 있다. 모델의 생성자와 역직렬화 모두 범위·일관성을 검증한다.

| 계약 | 주요 값 | 단위·누락 의미 |
| --- | --- | --- |
| `BabyProfile`, `CarePreferences` | 프로필 ID, 월령, 보호자 설정 간격·선호 수량 | 월령 0~24, 간격은 분, 수량은 mL. null은 미설정이며 권장값으로 자동 대입하지 않음 |
| `CareEvent`, `CareRecord` | 안정적인 ID, 아기 ID, 종류, 시각, 선택 수량, 입력 출처, 스키마 버전 | 시각은 UTC epoch 밀리초. 수량은 수유에만 허용. 기록 0건은 정상 상태 |
| `JourneySnapshot` | 목적지, ETA, 남은 거리 | ETA는 UTC epoch 밀리초, 거리는 미터. 내비 원시 단위를 확인한 어댑터만 변환해 채움 |
| `DriveSession` | 보호자가 확인한 착석/세션 시작·종료 | UTC epoch 밀리초. 시동·좌석 센서로 아기를 감지했다는 의미가 아님 |
| `VehicleContext` | 온도·속도·조향각 | 섭씨, m/s, 도. 승인된 공급자만 채우며 알 수 없는 값은 null |
| `CareFacility`, `StopCandidate` | 시설 종류·편의시설, 경로 접근성, 시설까지 시간/거리 | 위도·경도는 도, 시간은 초, 경로 거리는 미터. 직선거리로 주행 시간을 만들지 않음 |
| `StopPlan` | 풀케어 또는 가까운 안전 정차, 후보와 실패 상태 | 접근 확인 후보만 허용. 풀케어 후보는 수유시설 존재 확인 필요 |
| `ForecastInput`, `ForecastResult` | 평가 시각, 단계, 예상 시점·근거·행동 후보, 모델 버전, 데모 여부 | UNKNOWN/정보 부족을 정상 결과로 다룸. 원인 확진·울음 확률을 나타내지 않음 |

`CareRecord.schemaVersion`은 현재 1이다. 향후 필드는 기본값/nullable을 고려하되, 지원하지 않는 스키마를 조용히 덮어쓰지 않는다.
필드 이름의 `EpochMillis`, `Minutes`, `Seconds`, `Meters`, `Degrees`, `Celsius`, `Ml`은 계약의 일부다.

## 출처와 실패

`DataSnapshot`은 출처(`CAREGIVER`, `VEHICLE_SDK`, `NAVI_SDK`, `PUBLIC_DATA`, `DEMO`), 상태, 관측 시각과 값을 함께 전달한다.

| 상태 | 처리 |
| --- | --- |
| READY | 값과 관측 시각이 모두 있어야 한다. 판단에는 `readyValue`로 접근 |
| LOADING / EMPTY | 아직 안 왔거나 값이 없음. 숫자 0·빈 경로로 바꾸지 않음 |
| UNSUPPORTED / PERMISSION_DENIED / FAILED | 기능별 짧은 실패 상태를 표시하고 기록·기본 안내는 유지 |
| STALE | 마지막 캐시는 표시할 수 있으나 현재 경로/차량 값으로 판단하지 않음 |

SDK 예외 전문, 계정, 토큰은 공용 응답이나 사용자 문구로 전달하지 않는다. 정보가 없다는 이유로 미승인 API를 재시도하지 않는다.

## 실데이터와 데모 교체

`SnapshotSource<T>`가 동일한 읽기 전용 StateFlow 계약을 제공한다. 실제 공급자는 SDK 연결 성공·권한·capability 확인 후 값을 내보낸다.
SDK 클라이언트 수명과 콜백 해제는 앱 어댑터가 소유하며, ViewModel과 판단 엔진은 SDK 객체를 직접 다루지 않는다.

`DemoSnapshotSource`와 `DemoJourney.create(nowEpochMillis)`는 첫 F2·F4 동선을 테스트할 합성 여정·기록·시설을 제공한다.
데모 공급자는 갱신해도 출처가 DEMO로 유지된다. 시설명·프로필 ID도 데모로 분리하며 실제 시설 위치와 정보로 사용하지 않는다.
화면에서 데모 표시를 항상 유지하고, 보호자의 실제 기록에 데모 이벤트를 병합하지 않는다.
데모 시설은 실제 내비 경유지 요청에 전달하지 않는다. `StopCandidate.canRequestNavigation`으로 출처와 접근성부터 확인한다.

내비 단위나 시설 접근성을 확인하지 못했다면 실데이터처럼 변환해 넣지 않는다. 지원하지 않는 차량에서도 데모를 선택해 동선을 검증할 수 있다.

## 예보 규칙의 경계

- 기존 샌드박스의 월령별 수유 간격은 테스트용 예시다. 이 계약에는 그 값을 제품 기본값으로 넣지 않았다.
- 보호자 설정·관측 이력·검토된 참조 모델을 구분한다. 실제 기록이 없는데 마지막 수유/수면 시각을 생성하지 않는다.
- 첫날에는 기록 확인·여정 기반 정차·체크리스트 같은 제한된 가치를 제공한다. 검증된 참조 모델이 없으면 예상 시각을 확정하지 않는다.
- 근거 없는 의학적 판단, 원인 확진, 정밀한 울음 발생 확률을 표시하지 않는다. 월령 기본 모델의 근거·적용 범위는 #4에서 검토한다.
