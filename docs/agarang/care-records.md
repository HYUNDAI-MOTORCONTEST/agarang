# 제출 앱 돌봄 기록 (#3)

구현 위치: frontend/app의 care UI·AtomicCareRecordStore와 shared의 CareRepository·CareJournal.
샌드박스 저장소와 별개이며, 실제 기록에 데모 데이터를 섞지 않는다.

## 사용 흐름

- 주차 중 프로필에서 월령 0~24개월과 선택 수유량을 저장한다. 간격·수량을 월령의 권장값으로 자동 채우지 않는다.
- 첫 화면의 수유·기저귀·수면 시작/종료는 한 번 누르면 기록한다. 수유량은 프로필의 선택값을 사용한다.
- 최근 기록 취소는 가장 최근 시각의 이벤트 한 건을 제거한다. 수면 종료를 취소하면 진행 중 수면 기록으로 돌아간다.
- 주차 중 최근 기록에서 시각(5분 단위)·수유량을 수정한다. 프로필을 바꿔도 기존 기록의 ID·수량·시각은 유지한다.
- 주행/제한 상태로 바뀌면 프로필·상세·목록 화면을 즉시 닫고, 기록·취소만 제공한다. 행동 실행 시 ViewModel에서도 제한을 확인한다.
- 기록 상세에서 이전 버튼·Back을 누르면 기록 목록으로, 목록·프로필·연결 화면에서는 홈으로 돌아간다. 홈의 Back은 Activity를 종료하지 않고 앱을 숨긴다.
- 버튼은 누르는 동안 배경색과 95% 축소로 반응한다. 애니메이션 없이 표시하고 실제 터치 영역은 줄이지 않는다.
- 기록·프로필은 앱 전용 파일에 저장한다. 서버·내비·새 차량 권한에 의존하지 않는다. 샌드박스 데이터는 자동으로 가져오지 않는다.

## 저장·복원 계약

- CareRecord v1을 UTF-8 JSON으로 저장하고 AtomicFile로 이전 완료본을 보호한다. 저장 확인이 끝난 결과만 StateFlow에 반영한다.
- CareRepository.records는 확인된 기록 변경을 예보 엔진(#4)에 전달할 입력 스트림이다. 엔진 자체는 이번 범위에 없다.
- 이벤트는 최신순이며 ID가 안정적이다. 같은 시각은 입력 순서를 유지한다. 빠른 중복 입력·수면 순서 역전·시계 역전·미래 시각 수정은 거부한다.
- 동시에 들어온 저장 요청을 대기열에 쌓지 않는다. 저장 중에는 버튼을 비활성화한다.
- 저장 실패/확인 실패 후에는 다시 읽기 전까지 추가 변경을 막는다. 디스크에 반영된 뒤 확인만 실패한 경우도 다시 읽어 일치시킨다.
- 잘못된 JSON·지원하지 않는 버전·데모 출처는 덮어쓰지 않는다. 오류를 표시하고 읽기 재시도를 제공한다.
- 이력은 자동으로 잘라 저장하지 않는다. 주차 중 목록 화면만 최근 20개를 보여 준다.

## 검증 결과 (2026-11-11)

**화면 검증 정정 (2026-11-12):** 아래의 616×324dp·308×324dp는 수동 GCP AVD가 1920×1080·320dpi로 잘못 구성된 상태에서 측정한 값이다. 기록 기능·저장 실패·Back 등의 동작 검증과, 정상 화면 규격의 시각 검증을 구분한다. 해당 캡처에서 시스템 UI가 겹치고 앱의 다음 내용이 잘려 보였으므로 완성된 UI·가독성 검증 근거로 제시하지 않는다. 기본 Pleos 기기 프로필은 2560×1440·160dpi이며 [에뮬레이터 주의점](../guides/pleos-dev.md)의 절차로 화면 규격을 다시 확인한다.

**화면 규격 수정 후 확인 (2026-11-12):** GCP AVD 설정을 백업하고 위 기본 프로필로 Cold boot했다. 차량 HOME 초기화 후 런처 경로로 같은 앱을 다시 열어, 운전 화면을 가리지 않고 공조 버튼·시스템 바가 겹치지 않는 것을 캡처로 확인했다. 앱의 실제 영역은 가로 **1682×1210dp**, 세로 **841×1210dp**(density 1)였다. 가로 주간·세로 주간/야간에서 기록·취소·목록·프로필·연결 버튼이 모두 화면 안에 들어왔고, 64dp 터치 영역과 24dp 간격·가장자리 여백을 확인했다. 캡처·측정값은 Git에서 제외한 `.dev/verification/display/2026-11-12/`에 둔다. 종료 시 주간 모드, P·속도 0, UxR 0을 확인했다. 앱 UI 코드는 이번 진단에서 변경하지 않았으며, 이는 표시 오류 수정과 배치 확인이지 제품의 시각 디자인 마감 완료를 의미하지 않는다.

로컬에는 JDK·Android SDK가 없어, 사용자 승인 후 기존 GCP 테스트 VM의 임시 작업 폴더에서 빌드하고 실행 중인 Pleos 에뮬레이터에 설치했다. JDK 21, Android platform 37, Build Tools 36.0.0·37.0.0을 사용했다. 새 라이선스 동의나 Pleos 이미지 설치는 하지 않았다.

```bash
./gradlew :frontend:app:assembleDebug :shared:build :backend:build --console=plain -Pandroid.builder.sdkDownload=false
adb install -r frontend/app/build/outputs/apk/debug/app-debug.apk
adb shell am start -W -n com.hmgchallenge.app/.MainActivity
```

- 앱 debug 빌드·설치 통과. 공용 42개·서버 1개 테스트 통과(실패·오류·스킵 0). 공용 테스트 중 이번 기록 기능에 추가한 17개는 복원·수정·수면과 취소·중복과 시간 역전·손상 데이터·저장 실패·동시 요청·확인된 값 구독을 검증한다.
- 실제 앱에서 프로필 생성, 기록 0건, 네 종류 기록, 최근 기록 취소, 프로세스 종료 후 ID·시각·수유량 복원을 확인했다. 기록 시각·수유량 수정과 프로필 변경 후 기존 이력 보존도 통과했다.
- 합성 기록으로 실제 쓰기 실패를 만들고, 기록 보존·추가 저장 차단·다시 불러오기를 확인했다. 손상 JSON과 지원하지 않는 스키마도 덮어쓰지 않고 오류를 표시했다. 점검 후 합성 기록과 파일 권한을 원래대로 복원했다.
- 네이티브 window bar를 끌어 landscape(window 2개)와 portrait(window 1개)를 전환했다. 실제 앱 영역은 각각 **616×324dp**, **308×324dp**(density 2)였다. 두 너비에서 주간·야간 화면을 캡처하고 기록 버튼 네 개와 취소 버튼의 표시, 64dp 이상 터치 영역, 대상 사이 24dp 이상 간격을 확인했다. 좁은 창의 수유량과 mL는 같은 줄에 표시한다.
- 주간·야간 버튼·본문 텍스트의 대비는 활성/누름 조합 9.41:1 이상이다. 이번 화면에서 비활성 버튼을 배경·카드 위에 합성해 계산한 최솟값은 주간 5.00:1, 야간 5.57:1이다(`contrast.json`).
- 주행 전환 시 저장하지 않은 프로필 초안이 닫히고 기존 프로필이 유지되며, 설정·목록을 숨기고 기록·취소만 제공하는 것을 확인했다.
- 실제 Back 키와 화면의 이전 버튼으로 기록 상세→목록, 목록·프로필·연결 화면→홈을 확인했다. 홈의 Back 뒤에도 동일 Activity와 프로세스가 남고, 앱을 다시 열면 같은 Activity로 돌아왔다.

주야간 확인에는 `adb shell cmd uimode night no`·`yes`를, 주행 확인에는 Virtual Console의 기어 D·속도 10km/h를 사용했다. 종료 시 야간 모드를 원래 값으로, 차량을 P·속도 0으로 되돌린다. 확인 명령은 `adb shell cmd uimode night`, `adb shell dumpsys car_service --services CarUxRestrictionsManagerService`다.
